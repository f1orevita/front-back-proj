## Про проєкт

Репозиторій містить два Node.js-застосунки з однаковою логікою та базою даних. Їх можна порівняти між собою:

| Застосунок | Папка | Порт | Опис |
|---|---|---|---|
| Вразливий | `payload/1-vulnerable-app` | 3000 | SQL-запити формуються конкатенацією рядків |
| Захищений | `payload/2-secure-app` | 3001 | параметризовані запити (Prepared Statements) |

> ⚠️ Вразливий застосунок створено лише для навчання. Запускайте його тільки локально.

## Технології

- Node.js, Express 4
- SQLite (`sqlite3`), база в пам'яті, створюється наново при кожному запуску
- HTML, JavaScript та Bootstrap 5 (інтерфейс у папці `ui`, Bootstrap підключається з CDN)

## Запуск

Застосунки незалежні. Запускайте їх у двох окремих терміналах:

```bash
cd payload/1-vulnerable-app   # або payload/2-secure-app
npm install
npm start
```

Після запуску відкрийте у браузері:

- http://localhost:3000 — вразлива версія
- http://localhost:3001 — захищена версія

## Можливості інтерфейсу

На сторінці дві форми: **вхід** (`POST /login`) та **пошук товарів** (`GET /search`).

- Кнопки швидкої підстановки payload-ів для демо.
- Під кожною відповіддю показано SQL-запит, який виконався на сервері.
- Кожен запит також виводиться в консоль сервера.

## Тестові дані

Користувачі (`users`): `admin`, `student`, `ivan`. Товари (`products`): ноутбук, клавіатура, миша.

Для звичайного входу використовуйте `student` / `12345`.

## Демонстрація атак

Усі payload-и вводяться у форми вразливого застосунку (порт 3000).

| Атака | Де вводити | Payload |
|---|---|---|
| Обхід авторизації | логін | `admin' --` |
| Тавтологія | логін | `' OR '1'='1' --` |
| Error-based | логін | `'` |
| UNION: логіни й паролі | пошук | `' UNION SELECT id, login, password FROM users --` |
| UNION: секрет адміна | пошук | `' UNION SELECT id, secret_note, 0 FROM users WHERE role='admin' --` |
| UNION: список таблиць | пошук | `' UNION SELECT 1, name, 0 FROM sqlite_master WHERE type='table' --` |

На захищеній версії (порт 3001) ті самі payload-и не спрацьовують: вхід повертає `401`, пошук повертає порожній результат, а одинарна лапка не викликає помилки.

## Як працює захист

```js
// вразливо
"SELECT * FROM users WHERE login = '" + login + "' AND password = '" + password + "'"

// безпечно
db.get("SELECT id, login, role, secret_note FROM users WHERE login = ? AND password = ?", [login, password], cb);
```

Значення передаються окремо від SQL-команди, тому введений текст завжди сприймається як дані, а не як код. Також у захищеній версії не повертається пароль і текст помилок бази.
